TrafficMonitor Manual

TrafficMonitor User's Guide

TrafficMonitor is a desktop network analysis tool for live packet capture, packet inspection, host and flow tracking, process-aware traffic investigation, historical session review, Windows shell notifications, and traffic control rules for throttling, priority marking, daily quotas, and scheduled enforcement. This guide explains the screens, actions, and everyday workflows available in the current application build.

What TrafficMonitor is best at

  • Capturing live network traffic from a selected interface.
  • Opening and saving .pcap capture files.
  • Inspecting packets with protocol tree and hex view.
  • Following conversations through flow and host pivots.
  • Surfacing process-level network behavior and risk signals.
  • Reviewing capture history across sessions, processes, and hosts.
  • Applying traffic control rules for bandwidth limits, priorities, quotas, and schedules.

Shortcuts

  • Ctrl + O opens a capture file.
  • Ctrl + S saves the currently displayed packets.
  • Up and Down move between packets.
  • Left jumps to the last packet.
  • Right jumps to the first packet.

Quick Start

If you are opening TrafficMonitor for the first time, this workflow gets you from launch to inspection in a few minutes.

Select a device. Choose the network adapter from the selector at the top of the main window.
Start capture. Use the Start button to begin collecting live traffic, or use File > Open... to inspect an existing .pcap file.
Watch the packet list fill. Select a packet to populate the protocol tree and hex pane.
Apply a display filter. In the Packets view, narrow the list with expressions such as dns, tcp.port == 443, or process contains chrome.
Pivot when you find something interesting. Use Flows, Hosts, History, Process Packets, or Statistics to move from raw packets into higher-level summaries.
Live capture is best for active troubleshooting. Opening a .pcap file is best for offline review, repeatable analysis, and report preparation.

Main Window

The main shell is organized around a menu bar, capture toolbar, tabbed content area, and status bar.

Area Description
File menu Open a capture file, save the currently visible packet set, or quit the application.
View menu Turn packet table columns on or off, including packet number, time, addresses, ports, process, and info.
Analyze menu Jump directly to Flows, Hosts / Endpoints, History, and Statistics.
Settings menu Open notification settings and the traffic control rules editor.
Guide menu Open this document in your default browser.
Toolbar Select the capture device, start or stop capture, clear a followed flow, switch views, zoom the packet grid, navigate packet selection, and import or export captures.
Status bar Shows total packets, packet rate, total size, and current status text such as Idle, Capturing, or save and open progress.

Packets View

The Packets view is the packet-by-packet inspection workspace. It combines filtering, a packet list, protocol dissection, and hex inspection in one screen.

Display filter

The filter bar above the table updates as you type. Use it to reduce noise before drilling into details.

  • arp
  • dns
  • tcp && ip.addr == 1.1.1.1
  • tcp.port == 443
  • process contains chrome
  • frame.len > 512 && not arp

Packet table

The table shows one row per packet. Available columns include packet number, timestamp, source and destination IP, protocol, ports, length, flags, PID, process name, and summary info.

Packet details

When you select a packet, TrafficMonitor loads two synchronized inspection panes:

  • Protocol: A hierarchical protocol tree for the selected packet.
  • Hex: A formatted hex dump. Clicking protocol ranges highlights matching bytes. Use the copy button to place the hex dump on the clipboard.

Navigation

Use the toolbar buttons or the keyboard bindings to move through packets. This is helpful when you are stepping through a handshake, replaying a flow, or validating packet ordering.

The save action exports only the packets that are currently visible after filters are applied. If you want the full dataset, clear filters before saving.

Flows View

The Flows view groups packets into conversations so you can analyze behavior at the transport level instead of packet by packet.

Each row summarizes direction, protocol, source and destination endpoints, packet count, byte count, first seen time, last seen time, and overall duration.

Follow Flow actions

  • Follow Flow: Applies a packet filter for the selected conversation direction.
  • Follow Flow (Both directions): Keeps the full exchange together.
  • Clear Flow Filter: Returns to the broader packet list.

The right-hand details panel expands the selected row with traffic split information, sent and received totals, and timing values that are useful for investigating a specific session.

Hosts and Endpoints

The Endpoints view builds a searchable host registry from observed traffic.

Search Match by IP, hostname, process, DNS, TLS, or port.
Visibility filters Hide local or private addresses, and optionally hide multicast or broadcast traffic.
Registry columns Host, IP, scope, packet count, byte count, processes, and TLS summary.
Host details See hostname resolution hints, traffic totals, sent versus received split, first seen and last seen timing, owning processes, DNS history, TLS server names, and certificate history when those observations exist.
Context action Show packets filters the investigation down to traffic involving the selected host.

Traffic History

History keeps long-lived context across capture sessions so you can compare what is normal with what appeared for the first time.

Sessions

Review when a capture started, how long it ran, which device it used, and which hosts or processes were newly observed during that session.

Processes

Search for an application and inspect first seen time, last seen time, session count, total traffic volume, and top remote endpoint.

Hosts

Review endpoint history from the host perspective and identify when a remote system first appeared in the environment.

Why it matters

Historical context helps answer questions such as "Have we seen this before?" and "Is this process talking to a new host for the first time?"

Process Investigation

The Process Packets area turns packet capture into process-centric investigation. It is especially useful when you need to understand which executable is talking, how risky that behavior looks, and what immediate action to take.

Overview filters

Filter the process list by High risk, Beacon, Unsigned, Exited, or Blocked. You can also search by process name or related metadata.

Investigation details

Selecting a process opens a details workspace with risk label, liveness label, baseline state, traffic totals, remote count, and time labels. Depending on the observed activity, TrafficMonitor can also show:

  • Detection scenarios and supporting evidence.
  • TLS and DNS insights.
  • Behavior deviations from learned process baselines.
  • An incident graph with a save-to-image action.
  • Investigation timeline events that can jump back to packets, including quota and enforcement alerts raised during live capture.
  • Conversation and session-cluster rollups with packet pivot buttons.

Response actions

  • Open folder: Locate the executable on disk.
  • Block network: Add a firewall block, either permanently or with a timed preset such as 15 minutes, 1 hour, or until application exit.
  • Restore network: Remove a previously applied block.
  • End process: Terminate the running process.
  • Show packets: Pivot back to the packet list for the selected process.
  • Export report: Save an incident-oriented report for the selected process.
Process analysis is a fast triage surface, not a replacement for full forensic validation. Use the packet list, flow pivots, and historical context together before taking high-impact action.

Statistics

Statistics provides an at-a-glance traffic summary for the current capture.

  • Top Processes: Applications ranked by total traffic usage.
  • Top Hosts: Remote hosts sorted by consumed traffic.
  • Top Traffic Types: Protocol and service buckets by traffic volume.
  • Top Conversations: Largest process-to-remote conversations.
  • Capture Summary: Total bytes, total packet count, and per-second rates.

This screen is best when you need fast prioritization before drilling into a packet, host, or process.

Traffic Control Rules

Traffic control rules move TrafficMonitor from observation into policy enforcement. Open them from Settings > Traffic Control....

Rule targets Create rules for a process, a host, or a specific process-to-host combination.
Host matching Host rules match remote IP addresses or CIDR ranges such as 8.8.8.8 or 142.250.0.0/16. They do not match by domain name.
Bandwidth limit Apply an outbound QoS throttle in Mbps. Use 0 to leave traffic unthrottled.
Priority Mark traffic with Windows QoS priority levels such as Background, High, or Critical.
Daily quota Set a per-day traffic budget in MB. When the quota is reached, the rule can notify only or notify and auto-block the matching traffic until the next local day begins.
Scheduler Limit a rule to selected days and time windows. Overnight ranges such as 22:00 to 06:00 are supported.
Persistence Rules are saved locally and reloaded with the application. QoS and firewall actions can trigger an elevation prompt when Windows needs admin approval.
Traffic control rules are strongest during live capture on Windows. Throttling and priority are applied through native Windows QoS policies, while quota auto-block uses Windows Firewall rules.

Notifications

TrafficMonitor can raise Windows shell notifications even while the main window is minimized.

Enable Windows notifications Master switch for all shell notifications.
New process first seen on the network Alerts when a new executable shows network activity during the current live session.
Risk score threshold Alerts when a process crosses the configured risk score threshold.
Beacon detection Alerts when repetitive beacon-like behavior is detected.
Soft traffic quotas Alerts on daily process traffic thresholds, unknown-host traffic volume, and DNS burst activity. These notifications are informational and also write investigation timeline events.

Notification-based quota alerts are separate from traffic control rules. Soft quota alerts warn you about suspicious or excessive usage, while traffic control rules can enforce shaping or auto-blocking.

Capture Files

TrafficMonitor supports import and export of capture files in .pcap format.

Open a capture

Use File > Open... or Ctrl + O to load a previously saved packet capture. Opening a file resets the current live session state and replaces the current packet list with the file contents.

Save a capture

Use File > Save As... or Ctrl + S to export the packet list that is currently visible on screen. This includes the effect of active display or flow filters.

Tips and Notes

  • Use Flows when the packet list is too noisy and you need a conversation-level pivot.
  • Use Endpoints when the main question is "Which host is this?" rather than "Which packet is this?"
  • Use History when you need to compare current behavior with earlier sessions.
  • Use Process Packets when you want to connect traffic to an executable and respond quickly.
  • Use Traffic Control Rules when you want repeatable shaping or enforcement instead of one-off manual blocks.
  • Clear filters before exporting if you want a full capture file instead of the current subset.
  • The application is strongest on Windows environments where process attribution and Windows notifications are available.
